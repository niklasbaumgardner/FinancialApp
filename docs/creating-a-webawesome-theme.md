# Creating a new Web Awesome theme

How to add a new selectable theme to this app, using the existing themes in
`finapp/static/css/src/themes/` as the model.

A theme is one CSS file that redefines Web Awesome's design tokens under a
`.wa-theme-<name>` class, plus three registrations (esbuild, JS, Python) that
make it buildable and selectable.

---

## 1. How theming works here

### The cascade layers

Every theme file starts by importing `../layers.css`, which declares the global
layer order:

```css
@layer wa-native, wa-base, wa-utilities, wa-color-palette, wa-color-variant,
       wa-theme, wa-theme-dimension, wa-theme-overrides;
```

A theme only ever writes into the last three:

| Layer | What goes in it |
| --- | --- |
| `wa-theme` | Token definitions (`--wa-color-*`, `--wa-font-*`, `--wa-space-*`, …) |
| `wa-theme-dimension` | Theme-private helper custom properties + the rules that consume them (see `glossy.css`) |
| `wa-theme-overrides` | Per-component CSS tweaks (`wa-card::part(header)`, `wa-callout { … }`) |

Colors themselves come from the layers *below*: a **palette**
(`color/palettes/*.css`, layer `wa-color-palette`) defines the raw hue scales
`--wa-color-red-05` … `--wa-color-red-95`, and **variants**
(`color/variants/*.css`, layer `wa-color-variant`) map a hue onto
`--wa-color-brand-*`, `--wa-color-danger-*`, etc. Your theme consumes those
scales; it should not define raw hex values for them.

### What loads at runtime

1. `bundle.css` → `webawesome.css` → imports `layers.css`, `native.css`,
   `utilities.css` and **`themes/default.css`**. So the `default` theme and the
   `default` palette are *always* loaded as a base — that is why `default` has
   no esbuild entry point of its own.
2. `esbuild.config.mjs` builds every theme listed in `entryPoints` to its own
   hashed file and writes `finapp/templates/includes.html`, which contains:
   - `STATIC_FILE_MAP` — `{ mellow: "/static/dist/esbuild/mellow.<hash>.css", … }`
   - `<link id="theme">` and `<link id="palette">`, whose `href` is filled from
     `user_settings.settings.theme` / `.color_palette`.
3. `base.html` puts `wa-cloak wa-<mode> wa-palette-<palette>` on `<html>` and
   inlines the rounding/spacing/border-width scales as a `style` attribute.
4. `theme.mjs` (`window.THEME = new Theme(...)`) adds the
   `wa-theme-<name>` class to `<html>` and re-points `<link id="theme">` when
   the user switches themes.

The important consequence: **the theme name is a single string that must match
in five places** — the CSS filename, the `.wa-theme-<name>` selector, the
esbuild entry point, `THEME_LIST`, and `VALID_THEMES`.

### Vendor themes are generated, yours is not

`themes/*.css` (except any you add) are copies of
`node_modules/@awesome.me/webawesome-pro/dist/styles/themes/*.css`, refreshed by:

```
npm run copy-wa-styles
```

That command does `cp -r` over `finapp/static/css/src`, so **edits to a vendor
theme file are silently overwritten on the next upgrade.** Always add a new file
with a name that is not in the vendor list (`active`, `awesome`, `brutalist`,
`default`, `glossy`, `matter`, `mellow`, `playful`, `premium`, `shoelace`,
`tailspin`). Same rule for `wa-color-overrides.css`, which is generated by
`brandOverrides()` in `esbuild.config.mjs` — don't hand-edit it.

## 2. Step by step

### Step 1 — pick a name

Lowercase, no dots, not a vendor theme name, and not colliding with another CSS
entry point name in `esbuild.config.mjs` (`bundle`, `nb-category`, the palettes,
…). `STATIC_FILE_MAP` keys are derived from the source filename's first
dot-segment, so `midnight.css` → key `midnight`. Examples below use `midnight`.

### Step 2 — copy the closest existing theme

Start from whichever vendor theme is visually nearest your target; you will
replace values, not structure.

```powershell
Copy-Item finapp/static/css/src/themes/mellow.css finapp/static/css/src/themes/midnight.css
```

Rough starting points:

- `default` — plain baseline, fewest opinions
- `mellow` (463 lines) — smallest full theme, soft/rounded
- `shoelace` / `awesome` — the most heavily tokenized
- `brutalist` — sharp edges, thick borders, lots of `wa-theme-overrides`
- `glossy` / `playful` / `active` — examples of using `wa-theme-dimension`

### Step 3 — rename the selectors

Replace every `wa-theme-mellow` with `wa-theme-midnight`. **Do not simplify the
selector lists.** They look redundant but each permutation is load-bearing:

```css
.wa-theme-midnight,
.wa-theme-midnight.wa-light,
.wa-theme-midnight .wa-light,
.wa-theme-midnight.wa-dark .wa-invert,
.wa-theme-midnight .wa-dark .wa-invert,
.wa-light .wa-theme-midnight,
.wa-dark .wa-theme-midnight.wa-invert,
.wa-dark .wa-theme-midnight .wa-invert {
  /* light-mode tokens */
}
```

Two reasons:

- `themes/default.css` is always loaded and defines tokens on bare `.wa-light` /
  `.wa-dark` (specificity 0-1-0). `<link id="theme">` is emitted *before* the
  bundle in `includes.html`, so a lone `.wa-theme-midnight` (also 0-1-0) would
  **lose** to default. The doubled `.wa-theme-midnight.wa-light` (0-2-0) is what
  actually wins.
- The `.wa-invert` and descendant forms are what make nested light-on-dark
  sections work.

The third block (shared/dimension tokens) uses its own list — keep that too.

### Step 4 — set the imports

```css
@import url("../layers.css");                     /* required: layer order */
@import url("../color/palettes/vogue.css");       /* the palette you design against */
@import url("https://fonts.bunny.net/css?family=…&display=swap");  /* optional webfonts */
```

The palette import is a convenience: it only takes effect when `<html>` also has
the matching `wa-palette-vogue` class, which comes from the user's
`color_palette` setting. Design your theme so it still reads correctly on the
`default` palette, because that is what an unset preference gives you.

### Step 5 — fill in the color tokens (light block, then dark block)

Define these in both blocks, in terms of palette scales (`var(--wa-color-neutral-20)`),
`color-mix(in oklab, …)`, or `oklch(from …)` — see `mellow.css:14-201` for a
complete pair.

```
surfaces      --wa-color-surface-raised | -default | -lowered | -border
text          --wa-color-text-normal | -quiet | -link
overlays      --wa-color-overlay-modal | -inline
depth         --wa-color-shadow
focus         --wa-color-focus
interaction   --wa-color-mix-hover | --wa-color-mix-active
per variant   --wa-color-{brand,success,warning,danger,neutral}-
                 fill-{quiet,normal,loud}
                 border-{quiet,normal,loud}
                 on-{quiet,normal,loud}
```

Also set `color-scheme: light` / `dark` and `color: var(--wa-color-text-normal)`
at the top of each block so native controls and scrollbars follow the theme.

The five variant blocks are mechanical: pick the tint numbers once (e.g.
`fill-quiet: 90`, `fill-normal: 80`, `fill-loud: 50` for light; `10 / 20 / 50`
for dark) and apply the same pattern to all five. That consistency is what makes
the runtime brand-color swap (`.red-brand`, `.teal-brand`, …) keep working.

### Step 6 — fill in the dimension tokens

Third block, shared by light and dark: fonts, sizes, space, borders, rounding,
focus ring, shadows, transitions, then component tokens (form controls, buttons,
panels, tooltips). `mellow.css:204-431` is a good template.

**Keep the `*-scale` indirection.** `base.html` writes user settings straight
onto `<html>`:

```html
style="--wa-border-radius-scale:1.4;--wa-space-scale:1.125;--wa-border-width-scale:2;"
```

and `Theme` sets them live from the Preferences sliders. So always express sizes
as `calc(var(--wa-*-scale) * …)`:

```css
--wa-border-radius-scale: 1;
--wa-border-radius-m: calc(var(--wa-border-radius-scale) * 0.375rem);
```

If you hardcode `0.375rem`, the rounding/spacing/border-width controls in
Preferences silently stop working *for your theme only*. Same for
`--wa-font-size-scale` and the shadow `*-scale` tokens.

### Step 7 — optional: dimension helpers and component overrides

```css
@layer wa-theme-dimension {
  .wa-theme-midnight {
    --inner-glow: inset 0 0.125rem 0 0 rgb(255 255 255 / 0.08);
    /* rules that consume the helper vars */
  }
}

@layer wa-theme-overrides {
  .wa-theme-midnight {
    h1, h2, h3, h4, h5, h6 { letter-spacing: calc(1em * -0.02); }
    wa-card::part(header) { border-bottom-style: dotted; }
  }
}
```

Everything in these layers **must** be nested under `.wa-theme-midnight`, or it
leaks into every other theme. If you need to reach into a Web Awesome
component's shadow DOM, use `::part()`; app-wide (theme-independent) component
tweaks belong in `wa-overrides.css` instead.

### Step 8 — register the entry point

`finapp/static/esbuild.config.mjs`, in the `// Themes` group of `entryPoints`:

```js
    midnight: "./finapp/static/css/src/themes/midnight.css",
```

This is what puts `midnight` into `STATIC_FILE_MAP` in the generated
`includes.html`.

### Step 9 — register in the client

`finapp/static/js/theme.mjs`:

```js
export const THEME_LIST = [
  "default",
  ...
  "tailspin",
  "midnight",
];
```

`THEME_LIST` drives the Preferences dropdown (`nb-preferences.mjs`) and is the
allow-list in `Theme`'s `theme` setter — an unlisted name falls back to
`THEME_LIST[0]`, so skipping this makes the theme unselectable.

### Step 10 — register on the server

`finapp/queries/user_settings_queries.py`:

```python
VALID_THEMES = {
    "default",
    ...
    "tailspin",
    "midnight",
}
```

Without this, `is_valid_user_setting` rejects the write and the choice won't
persist across page loads.

### Step 11 — build and verify

```powershell
npm run es-build     # or: npm run es-watch
```

Then confirm the generated `finapp/templates/includes.html` contains a
`midnight:` key in `STATIC_FILE_MAP`. Start the app and switch to the theme
either through **Preferences → Theme preferences → Builtin Themes** or with the
GET shortcut (logged in):

```
/update_settings?theme=midnight
/update_settings?theme=midnight&color_palette=vogue&mode=dark
```

Tailwind (`npm run tw-build`) is unrelated to themes; you only need it if you
also touched `css/src/tailwind.css`.

## 3. Review checklist

- [ ] Light **and** dark mode, plus a `wa-invert` region if you use them.
- [ ] All nine palettes, or at least `default` + the one you imported.
- [ ] Rounding, spacing and border-width sliders in Preferences still move things.
- [ ] Brand/danger/success/warning/neutral color swaps (`.teal-brand`, …).
- [ ] Text contrast on `surface-raised`, `surface-default`, `surface-lowered`,
      and on every `fill-loud` (the `on-loud` pairing).
- [ ] Focus ring visible on buttons, inputs, dropdown items, and links.
- [ ] Overlay/modal surfaces: `nb-category-modal`, `nb-delete-budget-modal`.
- [ ] Data grid — `ag-grid-overrides.css` reads theme tokens; check both modes.
- [ ] Header/nav in `wa-page` at desktop and mobile breakpoints (1024px).
- [ ] No unstyled flash: `wa-cloak` is removed only once `wa-page` is defined.
- [ ] Nothing outside `.wa-theme-<name>` — switch to another theme and confirm
      it's unaffected.

## 4. Minimal skeleton

```css
@import url("../layers.css");
@import url("../color/palettes/default.css");

@layer wa-theme {
  .wa-theme-midnight,
  .wa-theme-midnight.wa-light,
  .wa-theme-midnight .wa-light,
  .wa-theme-midnight.wa-dark .wa-invert,
  .wa-theme-midnight .wa-dark .wa-invert,
  .wa-light .wa-theme-midnight,
  .wa-dark .wa-theme-midnight.wa-invert,
  .wa-dark .wa-theme-midnight .wa-invert {
    color-scheme: light;
    color: var(--wa-color-text-normal);
    /* surfaces, text, overlays, shadow, focus, mixes, 5 variant groups */
  }

  .wa-theme-midnight.wa-dark,
  .wa-theme-midnight .wa-dark,
  .wa-theme-midnight.wa-invert,
  .wa-theme-midnight .wa-invert,
  .wa-dark .wa-theme-midnight,
  .wa-light .wa-theme-midnight.wa-invert,
  .wa-light .wa-theme-midnight .wa-invert {
    color-scheme: dark;
    color: var(--wa-color-text-normal);
    /* same token set, dark values */
  }

  .wa-theme-midnight,
  .wa-theme-midnight.wa-light,
  .wa-theme-midnight .wa-light,
  .wa-theme-midnight.wa-dark,
  .wa-theme-midnight .wa-dark,
  .wa-theme-midnight.wa-invert,
  .wa-theme-midnight .wa-invert {
    font-family: var(--wa-font-family-body);
    /* fonts, space, borders, rounding, focus, shadows, transitions, components */
  }
}

@layer wa-theme-overrides {
  .wa-theme-midnight {
    /* component tweaks */
  }
}
```

## 5. Files touched

| File | Change |
| --- | --- |
| `finapp/static/css/src/themes/<name>.css` | new theme (only hand-written file) |
| `finapp/static/esbuild.config.mjs` | add entry point under `// Themes` |
| `finapp/static/js/theme.mjs` | add to `THEME_LIST` |
| `finapp/queries/user_settings_queries.py` | add to `VALID_THEMES` |
| `finapp/templates/includes.html` | regenerated by the build — don't edit |
